# ジョブからテーブルへの静的解析ツール

JavaソースとMyBatis XML、DDLから、ジョブがアクセスするテーブルと操作を抽出し、Excelにまとめます。
処理の流れは「Java構文JSON → 解析結果JSON・アクセスCSV → CSVからExcel生成」です。

## 前提条件

ツールを実行するPCで、PythonとJDKのコマンドが使用できることが前提です。

| 必要なもの | 用途 | インストール済みか確認するコマンド |
| --- | --- | --- |
| Python | 解析とExcel生成 | `python --version` |
| JDK | Java抽出ツールのコンパイルと実行 | `java -version` と `javac -version` |

PowerShellで上記のコマンドを実行し、それぞれのバージョンが表示されれば、この端末から使用できます。「コマンドが見つからない」場合は、未インストールか、インストール先にPATHが通っていない可能性があります。JDKはjavaだけでなくjavacも確認してください。

## 事前準備（初回）

Excel生成に必要なライブラリopenpyxlをインストールします。

```powershell
python -m pip install -r tools/requirements-excel.txt
```

## 実行手順

以下のコマンドも、このREADMEがあるプロジェクトのルートフォルダで実行します。

### 1. 解析対象を用意する

| 解析対象 | 用意するもの | このサンプルの場所 |
| --- | --- | --- |
| Javaソース | 解析したいアプリの.javaファイルを含むフォルダ | sample/java/src/main/java |
| Mapper XML | SQLを記述したMyBatis XMLを含むフォルダ | sample/java/src/main/resources |
| DDL | CREATE TABLEをまとめたファイル1つ | sample/java/src/main/resources/schema.sql |

サンプルを試す場合は、同梱ファイルをそのまま使えます。実ソースを解析する場合は、次のコマンドにそれぞれのパスを指定してください。解析対象のJavaソースを事前にコンパイルする必要はありません。

### 2. ソースを解析する（Java）

```powershell
python tools/analyze_java.py --java-dir sample/java/src/main/java --mapper-dir sample/java/src/main/resources --ddl sample/java/src/main/resources/schema.sql --output-dir out
```

| 引数 | 指定するもの |
| --- | --- |
| --java-dir | Javaソースのフォルダ（配下を再帰検索） |
| --mapper-dir | Mapper XMLのフォルダ（配下を再帰検索） |
| --ddl | テーブル定義をまとめたDDLファイル1つ |
| --output-dir | 解析結果の保存先 |
| --source-regex（任意） | フルパスを`/`区切りに統一して正規表現で部分一致。<br>例：`--source-regex '(^\|/)funcname/'`。<br>省略時は全件、Javaが0件ならエラー。参照先は自動追加せず、対象外の共通クラス等は追跡不可。Mapper XMLにも同じ正規表現を適用 |

実ソースを解析するときは、上記のパスを変更します。相対パスは実行フォルダが基準です。任意の--source-regex以外の引数を省略するとエラーになります。出力先はなければ作成し、同名ファイルは上書きします。

DDLは次の形を想定します。CREATE TABLE直前のコメントからテーブル論理名も取得します。コメントがない場合は物理名だけを表示します。

```sql
-- ENT01:テーブル論理名
CREATE TABLE TABLE_PHYSICAL_NAME (
  id BIGINT
);
```

#### このコマンドの出力

上記の解析コマンドでは、outフォルダに次のファイルを出力します。

| ファイル | 用途 |
| --- | --- |
| java_syntax.json | Javaのクラス・メソッド・呼び出しなど。名前付きレコードを並べたJSON配列 |
| job_data_flow_analysis.json | 呼び出し関係、到達メソッド、アクセス、未解決情報を含む調査用の解析結果。後続のPython解析・Excel生成では使用しません。サンプル検証用のverify.pyでは使用します |
| job_table_accesses.csv | ジョブ・テーブル・操作・根拠経路・XML・statement・テーブル論理名。Excelの入力 |
| ExtractSyntax.class / ExtractSyntax$1.class | Java抽出ツールをコンパイルした実行用ファイル |

Java構文JSONの項目説明はtools/ExtractSyntax.javaの冒頭コメントにあります。抽出ツールだけをコンパイルし、解析対象のJavaは構文として読みます。解析処理のPythonは標準ライブラリだけを使い、Excel生成だけがopenpyxlを使います。


### 3. ソースを解析する（Python）

Java解析の後、Excel生成の前に実行します。

```powershell
python tools/analyze_python.py --python-dir sample/python --ddl sample/java/src/main/resources/schema.sql --properties sample/python/jobs.properties --output out/job_table_accesses.csv
```

| 引数 | 指定するもの |
| --- | --- |
| --python-dir | Pythonジョブのフォルダ（配下を再帰検索） |
| --ddl | テーブル定義をまとめたDDLファイル |
| --properties（任意） | INSERT先を定義したUTF-8プロパティファイル。この手順では指定 |
| --output | 手順2で生成したテーブルアクセス一覧。既存ファイルへ追記 |
| --source-regex（任意） | フルパスを`/`区切りに統一して正規表現で部分一致。<br>例：`'/JOB0.+\.py$'`。<br>省略時は全件 |

正規表現は部分一致で判定します。完全一致を指定する場合は`^`と`$`を付けます。該当ファイルが0件ならエラーです。プロパティも選択したPythonジョブの設定だけを取り込みます。CSVは追記方式なので、以前の対象行を消して絞り直す場合はJava解析から再生成してください。

拡張子を除いたファイル名をジョブIDとします。Pythonファイル全体をテキストとして読み、DDLのテーブル名を検索します。構文解析やトークン分割は行わないため、Pythonの構文エラーがあるファイルも検索できます。引用符・SELECTの有無は問わず、大文字・小文字は区別しません。名前の前後に文字・数字・アンダースコアが続く部分一致は除外します。日本語などのUnicode文字も、この「文字」に含みます。見つかったテーブルはSELECT(推定)、プロパティの書き込み先はINSERTとして追記します。

| 出力 | 内容 |
| --- | --- |
| --outputで指定した既存CSV | Javaの行を残してPythonのアクセスを追加。path列にファイルと行番号、xml列は空欄 |


Pythonファイルは実行しません。コメント・変数名・説明文も対象なので、実際にはアクセスしない名前も拾う場合があります。変数展開・文字列連結や他ファイルの値は追跡しません。文字コード宣言は読み取りますが、文字コードが不正なファイルは読み込みエラーになります。同じファイル名が複数ある場合もエラーです。同じ行の再追記は防ぎますが、変更・削除前の行は自動削除しないため、更新時はJava解析から再生成してください。解析結果JSONにはPythonの情報を追加しません。

#### Pythonのテーブル名検索の仕組み

`tools/analyze_python.py` の `read_selects` で、次の順に処理します。

1. Pythonファイルをテキストとして読みます。ASTによる構文解析も、ソースの実行も行いません。`tokenize.open` は文字コード宣言の読み取りにだけ使用します。
2. 各行を大文字に揃え、DDLのテーブル名を正規表現で検索します。引用符・SQL・コメント・変数名の区別はしません。
3. 見つかったテーブル名と行番号を記録し、そのファイルのジョブIDに対する `SELECT(推定)` として追記します。

検索式は `(?<!\w)` + エスケープしたDDLのテーブル名 + `(?!\w)` です。テーブル名の直前・直後が文字・数字・アンダースコアなら一致させません。`\w` は日本語などのUnicode文字も含むため、英数字だけの判定ではありません。DDL名に含まれるドットなどは、正規表現の記号ではなく文字そのものとして照合します。

#### ヒットする例・しない例

以下は、DDLに `ORDERS` が登録されている場合です。

| ファイル内の記載 | 判定 | 理由 |
| --- | --- | --- |
| `"ORDERS"` / `'orders'` | ヒット | 引用符の種類と大文字・小文字は問わない |
| `SELECT * FROM ORDERS` | ヒット | SQLの構文としてではなく、名前を検索する |
| `# ORDERS を参照` | ヒット | コメントも対象で、名前の前後は空白 |
| `# ORDERSを参照` | ヒットしない | 名前の直後に日本語の文字が続く |
| `ORDERS = ...` | ヒット | 変数名も検索対象 |
| `schema.ORDERS` | ヒット | ドットは名前の境界として扱われる。スキーマの妥当性は判定しない |
| `ORDERS_ARCHIVE` / `MY_ORDERS` | ヒットしない | 名前の前後にアンダースコアが続く |
| `ORDERS2` | ヒットしない | 名前の直後に数字が続く |
| `"ORD" + "ERS"` | ヒットしない | 文字列を連結して評価しない |
| `table_name` | ヒットしない | 変数の値や別ファイルの定義を追跡しない |

DDLにない名前は出力しません。DDLに `schema.ORDERS` が登録されている場合は、そのスキーマ付きの名前を検索します。

#### 推定・重複・再実行の扱い

| 項目 | 動作 |
| --- | --- |
| 操作 | ソース内で見つかったものは、実際の用途が読み取り・書き込み・未使用のどれでも `SELECT(推定)`。プロパティから取得する `INSERT` は別に残す |
| Excel | 推定分は入力側に配置し、DFD・CRUD一覧のテーブル論理名に「★推定」を付ける |
| 同じ行に同じテーブル名が複数ある | 1件にまとめる |
| 別の行に同じテーブル名がある | テーブルアクセス一覧には行番号の異なる根拠として残す。Excelでは同じジョブ・テーブル・操作を1件にまとめる |
| 同じ結果を再実行 | 同一の出力行は追加しない |
| ソースを変更・削除した後の実行 | 追記だけでは古い行が残る。Java解析 → Python解析 → Excel生成の順に再実行する |
| 構文エラー | Pythonの文法は検査しないため、構文エラーがあってもテキスト検索できる。ファイルや文字コードの読み込みエラーは別途発生する |
| 別ファイル | 呼び出しやimportは追跡しない。対象フォルダ内の各Pythonファイルを、それぞれファイル名に基づく別ジョブとして扱う |

複数ファイルを結合して1ジョブとして検索する場合は、文字コードを揃え、ファイルの境目に改行を入れてください。結合後のファイル名がジョブIDになります。元ファイルも対象に残すと別ジョブとして解析されるため、対象フォルダや `--source-regex` で結合後のファイルだけを選びます。

### 4. CSVからExcelを生成する

```powershell
python tools/generate_excel.py --input out/job_table_accesses.csv --job-names tools/job_names.tsv --ddl sample/java/src/main/resources/schema.sql --output out/job_table_accesses.xlsx
```

| 必須引数 | 指定するもの |
| --- | --- |
| --input | 手順2で生成したテーブルアクセスCSV |
| --job-names | ジョブの表示設定TSV |
| --ddl | テーブル表示順に使うDDLファイル（CREATE TABLEの記載順） |
| --output | Excelの保存先ファイル |

#### ジョブの表示設定TSV

ジョブの表示設定はUTF-8のTSVです。サンプルはtools/job_names.tsvにあります。

以下はその内容です。列の区切りはスペースではなくタブです。先頭の見出し行を含め、4列すべてを指定します。

```text
job_id	logical_name	function_name	color
J001	配送依頼作成	配送	#E3EFFA
J002	出荷情報作成	出荷	#E5F2E6
J003	出荷時刻更新	出荷	#E5F2E6
J004	登録管理・出荷参照	集計	#EEE6F7
```

| 列名 | 内容 |
| --- | --- |
| job_id | CSVと照合するジョブID |
| logical_name | ジョブの論理名 |
| function_name | 2文字の機能名。例：配送。括弧付きで表示 |
| color | ジョブ欄の背景色。例：#E3EFFA |

未登録IDはジョブIDだけを表示します。必須欄の空欄・重複ID・不正な色はエラーになります。

Excelには、テーブルアクセス一覧に含まれるジョブをID順に「入力・ジョブ・出力」の3列で縦に並べます。テーブル名・論理名・操作はテーブルアクセス一覧から取得します。入力・出力の各欄はDDLのCREATE TABLE記載順で並べます。DDLにない表は末尾に名前順で表示します。テーブルへのアクセスがなく、一覧に含まれないジョブは出力しません。
6行目には移動先も含めて見出しを横に5組用意し、6行目まで固定します。機能名・ジョブ名・IDは同じセルに左揃えで表示します。

配置やモード・パラメーターの追記はExcel上で行います。再生成すると手編集は上書きされるため、編集用コピーを保存してください。

#### このコマンドの出力

| ファイル | 用途 |
| --- | --- |
| out/job_table_accesses.xlsx | 編集用のジョブ別入出力一覧。保存先は--outputで指定 |

Excelには「DFD」と「CRUD一覧」の2シートを出力します。「CRUD一覧」は機能名・ジョブ論理名・ジョブ物理名（ジョブID）・テーブル論理名・テーブル物理名・操作の6列です。同じジョブ・テーブル・操作は1行にまとめ、ジョブID順、DDLのテーブル記載順で並べます。見出し行を固定し、フィルターで絞り込めます。

### サンプルの検証（必要な場合）

```powershell
python tools/verify.py
python tools/verify_sql.py
```

解析やExcel生成から自動では実行されません。既存サンプルの想定結果とSQL抽出を確認するためのテストです。実ソースの正しさを保証するものではありません。

## 解析の照合規則と制約

### 照合規則

| 対象 | 判定方法 |
| --- | --- |
| ジョブの入口 | example.job配下のジョブ別パッケージにある、引数なしのmainProcess |
| Javaの呼び出し | 宣言型・importからクラスを特定し、メソッド名と引数個数で照合。入口から到達する呼び出しをたどる |
| Mapper XML | インターフェースの完全修飾名とnamespace、メソッド名とstatementのidを照合 |
| テーブル | SQLを区切り文字で分割し、DDLから取得したテーブル名と照合。大文字・小文字は区別しない |
| 操作 | 直前がINSERT INTOならINSERT、DELETE FROMならDELETE、UPDATEならUPDATE。それ以外はSELECT |

### Javaの呼び出しをどこまでたどるか

ジョブのmainProcessを入口に、呼び出し先のメソッドを順にたどります。

| 呼び出しの種類 | たどる範囲 |
| --- | --- |
| 通常のクラスのメソッド | 読み込んだソースからメソッドが一つに決まれば、その中の呼び出しも続けてたどる |
| 通常のインターフェースのメソッド | メソッド宣言までは接続するが、実装クラスには進まない。実装側のテーブルアクセスは取得できない |
| MyBatisのMapper | インターフェースのメソッドから、対応するMapper XMLのSQLを解析する |
| 入口から呼ばれないメソッド | 対象外。親クラスのbeforeProcessなども、定義されているだけではたどらない |

### 未解決の呼び出し（unresolved）の意味

呼び出し元は分かっていても、呼び出し先のメソッド宣言を一つに決められなかった呼び出しを記録します。

| 条件 | 記録する内容 |
| --- | --- |
| 候補が見つからない | 外部ライブラリ、読み込んでいないクラス、未対応のローカル変数・引数経由などの呼び出し |
| 候補が複数ある | メソッド名と引数個数が同じで、一つに決められない呼び出し |

解析結果JSONの全体のunresolvedには抽出した呼び出しの未解決分を、ジョブ別のunresolvedには入口から到達したメソッド内の未解決分だけを記録します。

**インターフェースのメソッド宣言に接続できた場合は、実装まで追えていなくてもunresolvedには入りません。** 未解決が0件でも、すべてのテーブルアクセスを取得できたことを意味しません。

### Javaソース内のテーブル名の補完

解析用Pythonスクリプトが、各ジョブのmainProcessから到達できたメソッドを定義するJavaファイルを直接読み、DDLのテーブル名を推定SELECTとして追加します。構文抽出ツールの出力形式は変更しません。

| 項目 | 方針 |
| --- | --- |
| 抽出対象 | 入口と到達メソッドを定義するJavaファイル全体。クラス定数・コメント・未使用の文字列も対象とする。同じジョブ・テーブルは1件にまとめる |
| 照合 | 大文字のDDLテーブル名をダブルクォートで囲んだ形をそのまま検索する。トークン分割や大文字変換は行わない |
| 操作 | Javaソースから見つかったものは、実際の用途にかかわらず推定のSELECTとする |
| Mapper XML | SQLから判定したSELECT・INSERT・UPDATE・DELETEは維持する。テーブル位置のプレースホルダーも元の表記で残す |
| 追跡しないもの | 定数からDTOへのセット、Mapperへの値の受け渡し、到達メソッドがないクラスの定数参照や文字列の組み立ては追跡しない |
| 注意点 | 未使用の定数や、実際は書き込みだけに使うテーブルもSELECTとして出る可能性がある。実際の読み取りを確認した結果ではない |

### 主な制約

| 対象 | 対応していないこと・注意点 |
| --- | --- |
| Java | DI・通常のインターフェースから実装への接続、引数型によるオーバーロード解決、ジェネリクス、可変長引数、連鎖呼び出し、ローカル変数・引数経由の呼び出し、static・ワイルドカードimportは未対応 |
| 構文と実行 | 内部クラス・メソッド参照は対象外。ラムダを含め、実行順・回数・分岐の実行有無は判定しない |
| SQL | 文法解析ではなく名前照合。列名・別名がテーブル名と同じ場合は過検出し、DDLにない表は拾わない。子要素を持つ動的SQL・includeは除外し、CTE・MERGE等の分類は保証しない |
| DDL | 1ファイル内のCREATE TABLE形式が前提。引用識別子や文法検証は未対応。schema.tableはスキーマ名を含めて一致させる |
| 確認先 | 未解決の呼び出しなどは解析結果JSONに記録。SQLは既知テーブルが1件も見つからない場合に要確認となり、未知テーブルの混在をすべて検出するわけではない |



















テーブル位置（FROM・JOIN・UPDATE・INSERT INTOの直後）のプレースホルダーは、実名を推定せず元の表記でテーブルアクセス一覧とExcelに出力します。解析JSONのSQL要確認事項にも記録します。値のパラメーターはテーブルとして扱いません。カンマ結合など、それ以外の位置の動的テーブル指定は未対応です。

Javaソースの文字列検索とPythonの文字列検索から補うアクセスは、操作を `SELECT(推定)` として出力します。XMLのSQLから判定した `SELECT` とは区別します。Excelでは推定分も入力側に配置し、DFD・CRUD一覧のテーブル論理名の末尾に「★推定」を付けます。論理名がない場合はDFDでは物理名の末尾、CRUD一覧では論理名欄に「★推定」を表示します。
